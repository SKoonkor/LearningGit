\section*{Solutions to Homework 9}

\textbf{Part A.}

\begin{lstlisting}
$ bash codeHints/L09/setup_hw9.sh
$ cd practice
$ git clone hw9_server.git hw9
$ cd hw9
$ bash test.sh
FAIL: got 'Helo, world'
$ sed -i.bak 's/Helo/Hello/' greet.sh && rm greet.sh.bak    # or edit by hand
$ bash test.sh
PASS
$ git commit -am "Fix greeting typo" -m "Closes #1"
$ mkdir -p .github/workflows .github/ISSUE_TEMPLATE
\end{lstlisting}

Create \code{.github/workflows/ci.yml} (spaces only):

\begin{lstlisting}
name: CI
on:
  push:
    branches: [main]
  pull_request:
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run the tests
        run: bash test.sh
\end{lstlisting}

Create \code{.github/ISSUE\_TEMPLATE/bug\_report.md} and \code{.github/pull\_request\_template.md}:

\begin{lstlisting}
---
name: Bug report
about: Something does not work
---

## What happened?

## What did you expect?
\end{lstlisting}

\begin{lstlisting}
## What does this change?

## Checklist
- [ ] The tests pass
- [ ] I read my own diff
\end{lstlisting}

\begin{lstlisting}
$ git add .github/workflows
$ git commit -m "Add CI workflow"
$ git add .github/ISSUE_TEMPLATE .github/pull_request_template.md
$ git commit -m "Add templates"
$ git tag v0.1.0 $(git rev-list --max-parents=0 HEAD)
$ git tag -a v1.0.0 -m "First release"
$ git push origin main v0.1.0 v1.0.0
$ printf 'next-bugfix=1.0.1\nissue-closes-when=merged\n' > ../hw9_answers.txt
\end{lstlisting}

(Part A checks only the workflow's words; GitHub reports wrong indentation in Part B.)

\textbf{9.3--9.4.} The checker runs your \code{test.sh} on a copy of the server's \code{main}, as the workflow does on GitHub. The second \code{-m} is a separate paragraph of the message; GitHub finds the keyword anywhere in it.

\textbf{9.5.} Without \code{uses: actions/checkout} the machine has no files, so \code{bash test.sh} fails. The folder is \code{.github/workflows} (with an \emph{s}).

\textbf{9.7.} The annotated tag has its own object with your message (\code{git show v1.0.0} shows a \emph{Tagger}). Tags are pushed only when you name them or use \code{--tags}.

\textbf{9.8.} Fixing a bug in \code{1.0.0} gives the patch version \code{1.0.1}. \code{Closes \#12} closes the issue when the change is \emph{merged} into the default branch, not when the pull request is opened.

\textbf{Part B.}

\begin{lstlisting}
(GitHub) New repository: ci-practice, Public, no README
$ git remote add github git@github.com:YOURNAME/ci-practice.git      # the SSH address
$ git push github main v0.1.0 v1.0.0
(GitHub) Actions tab: the "CI" workflow ran: green tick
$ printf 'repo=YOURNAME/ci-practice\n' >> ../hw9_answers.txt
(GitHub) Issues > New issue "Add a note to the README"  -> number 1
$ git switch -c readme-note
$ echo "Notes coming soon." >> README.md
$ git commit -am "Add a note to the README"
$ git push github readme-note
(GitHub) Open the pull request, description "Closes #1"; wait for the green check; Merge
(GitHub) Issue #1 is now closed
$ printf 'issue=1\n' >> ../hw9_answers.txt
(GitHub) Releases > Draft a new release > tag v1.0.0 > Generate release notes > Publish
(GitHub) Actions: wait until the new run on main (after the merge) is green, then run the checker
\end{lstlisting}

Replace \code{YOURNAME} with your GitHub user name. The checker needs the answers file to contain \code{repo=}, \code{issue=}, and a remote of \code{practice/hw9} that points at that repository. It then asks GitHub's public interface whether the issue is closed, whether a release exists for \code{v1.0.0}, and whether the latest Actions run on \code{main} succeeded. If the last check is red, open the run's log in the Actions tab.

\Needspace{8\baselineskip}
\textbf{Common mistakes.}
\begin{itemize}
  \item A \emph{tab} in the workflow, or a folder \code{.github/workflow} instead of \code{workflows}.
  \item Creating Issue \#1 \emph{before} the first push: the commit message \code{Closes \#1} then closes it at once, and the pull request closes nothing. Push first, then create the issue.
  \item Forgetting to push the tags: \code{git push origin main} sends no tags.
  \item Creating the repository with a README: the first push is rejected. Create it empty.
  \item A private repository: the checker cannot see it and reports ``cannot find''.
  \item Running the checker while the workflow run on \code{main} is still in progress: the check ``latest run is green'' fails until it finishes. Wait and run it again.
\end{itemize}
